# Architecture Rules

Full detail: `docs/architecture/module-boundaries.md`. This is the
short version to keep in your head while writing code.

1. **Storage owns SQL. Nothing else does.** If you are writing a
   `SELECT`/`INSERT`/`UPDATE`/`DELETE` outside `reva_core/storage/`,
   stop — add or extend a repository instead.
2. **API owns transport, not domain logic.** A route handler in
   `reva_core/api/` should be a few lines: parse, call orchestration/a
   repository, return. No business rules in a handler.
3. **Orchestration never calls a vendor SDK directly.** Provider calls
   go through a `models/` Protocol so a fake can stand in during tests.
4. **No tool executes without going through policy.** This is true
   today by construction (`tools/`/`policy/` don't exist yet); when
   they do, orchestration must not have a path that skips policy.
5. **No arbitrary command execution, ever.** No `subprocess.run` /
   `os.system` / `eval` / `exec` on untrusted or model-generated input.
   Not "sandboxed" — absent. See ADR-012.
6. **Every durable/serialized contract has `schema_version` and only
   accepts timezone-aware UTC datetimes.** Use `VersionedModel` and
   `UtcDatetime` from `reva_core/shared/contracts/base.py`.
7. **Every entity ID is UUIDv7, generated by `shared/ids.py`.** Never a
   SQLite `ROWID` used as cross-device identity.
8. **Secrets never enter normal logs or audit metadata.** Use
   `SecretStr` in config; the redaction key list in
   `shared/redaction.py` is the single source of truth — extend it,
   don't work around it.
9. **Don't build ahead of need.** No plugin marketplace, generic
   workflow engine, agent framework, or microservice split without a
   concrete requirement and a new ADR (`docs/architecture/future-expansion-policy.md`).
   A directory with only a `README.md` saying `Status: PLANNED` is
   correct; an empty Python package "for later" is not.
10. **A new persisted field or table needs a new migration file**,
    never a hand-edited existing one — migrations are append-only.
