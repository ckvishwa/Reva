# Android operation modes (C3b)

`ModeController` derives the visible Paired, Standalone, and Offline-lite modes from saved owner choices and fresh availability. A restart begins Offline-lite until a paired PC or hosted key/network is observed. Paired requires an existing trusted pairing and a recent successful sync; its existing sync and PC action traffic uses the signed, TLS-pinned gateway. Standalone requires a separately stored provider key, network, and the owner's hosted-processing switch. Automatic transition from Paired to Standalone needs a second explicit switch. Offline-lite uses local rules and Rust Kernel-backed queries; open questions explicitly state that advanced reasoning is unavailable.

The Anthropic Messages client sends one text question and a fixed system instruction to the fixed HTTPS endpoint. It sends no audio, screen capture, Kernel rows, or tool declarations. It cannot approve or execute actions. The key is wrapped by Android Keystore and its ciphertext is stored in `noBackupFilesDir`. A request has a seven-second deadline; transport failure or timeout moves to Offline-lite until the owner retries. Consent or mode revocation discards an in-flight answer. Because a local word filter cannot reliably classify arbitrary free-form questions, **both Finance and Memory consent are required for any hosted question**. Turning either off closes the whole hosted egress path. The text gate remains a second conservative guard.

Paired open-question reasoning currently returns the Offline-lite advanced-reasoning message. The signed gateway has no generic paired planner endpoint. Local Today questions and phone/PC actions remain available by their existing routes. This is a remaining C3 mode gap, not a completed paired-brain feature.

Owner-facing controls are under More, with current mode/reason shown in Talk. Cloud is off by default. Provider, destination, sent data, model, domain consent, stored-key state, and timeout retry are visible in More.
